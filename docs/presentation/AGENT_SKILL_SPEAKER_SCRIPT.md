### [Slide 3] 핵심 패러다임: Agent vs Skill (02:30 ~ 04:00)
> **발표자 멘트**:  
> "이 문제를 해결하기 위해 Antigravity가 제시하는 가장 핵심적인 두 가지 개념이 바로 **'Agent'**와 **'Skill'**입니다.  
> 많은 분들이 이 둘의 차이를 헷갈려하시는데요, 이렇게 기억하시면 가장 쉽습니다.  
> **Agent는 '사람(전문가 페르소나)'**입니다. 각 에이전트는 기획, 백엔드, 프론트엔드처럼 본인만의 직무가 정해져 있고, 서로 다른 독립된 Git 브랜치나 워크스페이스에서 작업합니다. 그리고 어려운 작업은 고성능의 `pro` 모델, 단순 조회나 검증은 빠르고 저렴한 `flash` 모델을 배치합니다.  
> 반면, **Skill은 그 에이전트가 손에 쥐는 '도구함이자 작업 매뉴얼'**입니다.  
> 아무리 훌륭한 백엔드 개발자라도 코드 포맷팅 도구나 테스트 러너가 필요하듯, 에이전트가 필요할 때 호출해서 쓰는 정적 분석 스크립트, 검증기, 문서 템플릿이 바로 Skill입니다.  
> 즉, `에이전트 = 역할과 영역 격리`, `스킬 = 도구와 자동 검증기`라는 공식입니다."

> 1. 기획을 전담하는 `spec-planner`는 기능 사양서만 작성하고 소스 코드는 손대지 못합니다.

> 4. `api-viewer`는 가벼운 `flash` 모델로 백엔드 코드와 문서가 일치하는지 정합성을 스캔하고 프론트엔드에 DTO 가이드를 넘깁니다.

>  
> 특히 표 우측의 **'절대 금지 작업(Forbidden)'**을 명시한 것이 핵심입니다. 각자의 영역 경계(Ownership Boundary)가 명확해야 파일 덮어쓰기나 사이드 이펙트가 원천 차단됩니다."

> 백엔드가 끝나면 Phase 2에서 `api-viewer`가 브릿지 역할을 하여 실제 API 스펙을 프론트와 QA에게 인계하고,  
> Phase 3에서 프론트가 실제 API를 바인딩하자마자 **QA 테스터가 자동으로 회귀 검증을 시작**합니다."

>    만약 **똑같은 에러가 연속 3번 이상 반복되면**, AI가 엉뚱한 방향으로 헤매는 환각 상태라고 판단하여 루프를 즉시 중단하고 `AUTONOMOUS_PIPELINE_REPORT.md`라는 상세 원인 분석 보고서를 자동으로 출력한 뒤 사람 개발자에게 에스컬레이션합니다.  
> 반대로 모든 검증이 100% 통과되면 자동으로 SUCCESS 보고서를 띄우고 배포 승인을 완료합니다."

## 🙋‍♂️ 발표 Q&A 예상 질문 & 모범 답변 10선

### Q1. 에이전트를 여러 개 띄우면 API 호출 비용(토큰)이 너무 많이 들지 않나요?
**모범 답변**:
> "오히려 단일 에이전트보다 토큰 비용이 절감됩니다. 단일 대화방에서는 대화가 길어질수록 10만, 20만 토큰의 누적 히스토리가 매 턴마다 전달됩니다. 반면 멀티 에이전트는 본인 도메인의 짧은 컨텍스트만 가지고 작업하며, 특히 단순 조회(`api-viewer`)나 QA(`qa-tester`)는 초경량/초저가 모델인 `flash`를 사용하기 때문에 전체 비용과 속도 면에서 훨씬 경제적입니다."

### Q2. 프론트엔드가 Mock Data로 작업하다가 백엔드와 연결할 때 스펙이 어긋나면 어떻게 하나요?
**모범 답변**:
> "그것을 방지하는 것이 Phase 0의 `spec_validator.py`와 Phase 2의 `api_inspector.py`입니다. Phase 0에서 이미 TypeScript 인터페이스와 Mock 데이터가 합의되었고, Phase 2에서 `api-viewer`가 백엔드 실제 구현 소스와 문서를 정적으로 비교 검증한 뒤 프론트에 넘겨주기 때문에 실제 연동 시 오차율이 거의 0%에 가깝습니다."

### Q3. 에이전트 간 통신(Handoff)은 어떻게 이루어지나요?
**모범 답변**:
> "규격화된 이벤트 메시지 계약(Handoff Message Contract)을 사용합니다. 예를 들어 백엔드가 끝나면 `BACKEND_API_COMPLETED` 이벤트와 함께 API 경로 및 Vitest 100% 통과 증빙을 전달하고, 이를 수신한 `api-viewer`가 동작을 시작하는 이벤트 기반 구조입니다."

### Q4. 컴포넌트 400줄 제한을 두는 이유는 무엇인가요?
**모범 답변**:
> "AI 에이전트는 파일 길이가 500줄을 넘어가면 코드의 앞부분을 수정하다가 뒷부분을 누락하거나 구조를 망가뜨리는 경향이 급격히 증가합니다. 또한 400줄 제한을 두면 자연스럽게 서브 컴포넌트로 책임 분리가 이루어져 가독성과 재사용성이 극대화됩니다. 저희는 이를 `component_reviewer.py`로 강제합니다."

### Q5. Skill과 일반 쉘 스크립트(CLI 도구)의 차이는 무엇인가요?
**모범 답변**:
> "단순 스크립트는 실행 코드만 있지만, Antigravity의 Skill은 `SKILL.md`라는 지침서(YAML 메타데이터 + 실행 절차 + 프롬프트 지침)와 스크립트, 레퍼런스, 템플릿이 한 폴더에 패키징된 구조입니다. 에이전트가 어떤 상황에서 이 스크립트를 어떤 파라미터로 호출해야 하는지 맥락을 완벽히 이해하고 스스로 판단하여 실행한다는 점이 다릅니다."

### Q6. 테마 색상 하드코딩 금지 규칙은 왜 에이전트 룰로 강제했나요?
**모범 답변**:
> "AI에게 스타일을 맡기면 `#ffffff`, `#1e1e1e` 같은 색상 코드를 무분별하게 인라인으로 넣는 경우가 많습니다. 이렇게 되면 다크 모드/라이트 모드 전환 시 글자가 안 보이거나 배경이 깨지는 결함이 발생합니다. 시맨틱 CSS 토큰(`var(--bg-card)`, `var(--text-main)`)을 강제해야만 테마 완벽 호환성이 보장됩니다."

### Q7. Windows 환경에서 `UTF-8 with BOM`을 강제하는 이유는?
